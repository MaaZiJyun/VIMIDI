# VIMIDI Studio

本地 MIDI 音乐可视化工作台。导入 `.mid` / `.midi` 和对应的 `.mp3` / `.wav`，同步预览钢琴瀑布，并导出带原始音频的 MP4 视频。

## 开始使用

需要 Node.js 20.19+ 和 npm。视频编码需要浏览器支持 WebCodecs H.264 与 AAC，建议使用最新版桌面 Chrome / Edge。远程部署需 HTTPS，本地 `localhost` 可直接使用。

```bash
npm install
npm run dev
```

打开 <http://localhost:3000>。

1. 拖入一个 MIDI 和一个音频文件，也可以分两次选择。
2. 播放、暂停或拖动时间轴。空格键可切换播放状态，编辑表单时不触发快捷键。
   拖动期间暂停音频，松开后等待音频定位完成，再按原先播放状态恢复。滑块可显示待定位的目标位置，画面与速度指示使用音频已经确认的位置，避免连续跳转时旧事件覆盖新请求。
3. 选择音符配色、时间窗、辉光、粒子、键盘和标题；按音轨控制音符显隐。
   音符使用整条纯色，未触键时较暗，触键后整体提亮；可调整粒子强度。选择「全局音符颜色」可统一所有音轨，点击「恢复分轨」恢复色板。
4. 如音符起点与录音不一致，调整 MIDI 时间偏移。正值表示音符延后。
5. 选择画幅、分辨率、帧率和导出区间，点击「导出 MP4」。默认导出前 30 秒以便检查效果，可切换完整音频。

文件在浏览器本地处理。预览音量仅影响监听；导出保留源音频音量。隐藏音轨只改变画面，因为混音 MP3 / WAV 无法按 MIDI 音轨静音。

在「视觉样式 → 背景图片」上传或替换 JPG / PNG / WebP 图片（最大 20 MB），图片居中裁切铺满画幅，不会拉伸。可调节「背景压暗」以突出音符，或点击「恢复默认背景」移除图片；预览与导出的 MP4 使用相同背景。背景图片仅在当前页面本地使用，刷新后需重新选择。

「从背景提取音符颜色」默认开启：上传或替换背景后，在本地提取最多 6 种有区分度的代表色，忽略透明像素、优先避开纯黑与纯白区域，合并近似颜色并适度调整亮度，生成「背景配色」色板。颜色按音轨循环分配，音符、触键高亮和粒子同步使用对应颜色；纯色图片仅生成一种颜色，不补造颜色。仍可手动统一颜色或切换色板，点击「恢复分轨」恢复当前色板，点击「背景配色」可切回图片取色；关闭开关后更换背景将保留当前配色，重新开启会立即从当前背景取色。移除背景不会重置音符颜色；透明图片等无法取色时保留原配色并显示提示。

钢琴键盘采用细长半透明样式，至少显示标准 88 键音域，避免少量音符时琴键被横向拉宽；超出标准音域的音符仍会显示。琴键保持纵向长度，仅保留轻微分隔线，无折面、反光条或厚重描边；触键时按音轨配色轻染提亮，背景可透过琴键，预览和导出效果一致。

「视频文字」面板可自定义 Header / 标题与 Footer / 页脚，留空隐藏对应文字。默认标题来自 MIDI 名称，点击「使用素材名」可恢复；页脚时间可独立关闭。文字与视觉设置同步应用到预览和 MP4。

## Auto BPM

MIDI 原生变速默认生效，不需要打开 Auto BPM。应用保留文件中的全部 Tempo Map，并按变速曲线换算音符起止时间；预览下方展示原始速度曲线、Tempo 事件数和精确到小数点后三位的当前 BPM。密集曲线仅在绘图时抽样，播放与导出使用完整数据。

提供的示例 MIDI 含 20,924 条原始 Tempo 事件，原生速度约 60–124 BPM，属于变速 MIDI。音频时长与 MIDI 不同并不意味着 MIDI 恒速，也不能据此判断未读取原生变速。

导入 MIDI 与音频后，打开「节拍同步 → Auto BPM」。应用使用 `realtime-bpm-analyzer` 的 tempogram detector，在浏览器 Worker 中每 12 秒分析一个音频窗口，显示进度、动态速度曲线、分段 BPM 与置信度。

分析完成后，以 MIDI 原始变速信息计算音符的音乐节拍位置，再根据音频的动态 BPM 曲线重新计算音符起止时间。跨越变速点的长音也保持正确的节拍长度。预览与导出使用同一个重新定时的 MIDI 项目，原音频的播放速度与音高保持不变。

- 分析逐段解码长音频，只保留当前 PCM 窗口；关闭开关、替换音频或离开页面会终止解码与分析线程。
- 分析中暂停视频导出；完成后可播放并导出。已完成的结果可在关闭、重新打开开关时复用。
- 半拍 / 倍拍候选以 MIDI 初始速度和前一段识别结果辅助选择。低置信度或静音段沿用前段速度；若全曲没有可靠节拍，会显示提示，可关闭 Auto BPM 使用 MIDI 原始时间。
- 12 秒是局部速度估计的分辨率，不是逐拍定位。乐曲剪辑差异、自由速度、弱节拍及半拍 / 倍拍歧义仍可能造成偏差；起点可用 MIDI 时间偏移校准。

## 你的本地示例

仓库根目录存在以下两个文件时，点击「载入你的示例文件」即可使用：

```text
All Tracks in FATE OF THE TREE (Original Mix)2.0.mid
all-songs-taiki.mp3
```

MIDI 约 61:18，包含 36 个有效音轨和 39,406 个有效音符；音频约 58:52，大小约 135 MB。两者长度不同，应用会显示提示。偏移只能对齐整体起点，不能自动修复速度差异、不同剪辑或局部错位。导出区间以音频时长为准。

「MIDI 播放位置」表示当前光标位置，不代表 MIDI 总时长；原始音符总时长单独显示。即使当前音频与 MIDI 的秒数相同，也不证明两份素材的音乐内容处于同一位置。

示例端点仅允许访问这两个固定文件，支持 HTTP 字节范围读取，不接受任意路径。源媒体文件已加入 `.gitignore`，不会作为应用静态资源打包；部署后若没有这些文件，可继续手动导入素材。

## 长视频与导出

- 浏览器原生音频元素播放压缩音频；导出通过 Mediabunny 按段解码，不一次性展开整段录音。
- 预览和导出共用 `drawFrame()`，导出使用确定性的时间戳逐帧渲染，不依赖屏幕录制或实时播放速度。
- 输出为 MP4，H.264 视频与 AAC 音频，支持 720p / 1080p、30 / 60 fps、16:9 / 9:16 / 1:1。
- 支持 File System Access API 时可启用「直接写入磁盘」，持续写入分片 MP4。取消导出会中止未完成的文件写入。
- 内存下载模式限制为 10 分钟以内；长视频请选择直接写盘或分段导出。完整长片的耗时取决于分辨率、帧率和硬件编码性能。
- 导出期间可以取消，相关文件导入和视觉控件锁定，防止中途修改。编码失败会显示可操作的错误。
- WebCodecs / 编码器不可用时会明确提示，不会将其他容器改名成 `.mp4`。不支持直接写盘的浏览器仍可下载短段视频。

## 代码结构

应用与测试逻辑使用 TypeScript / TSX，严格模式；样式使用 CSS 和 Tailwind。业务模块通过类型与显式参数通信，不依赖全局单例。

```text
src/app/
  page.tsx                    页面入口
  api/example/route.ts        固定本地示例的流式读取
  o-ui-tokens.css              o-ui 原始设计变量
  styles/                     按界面职责拆分的样式
src/features/studio/
  model/                      类型、默认设置、时间与尺寸规则
  midi/                       MIDI 解析和音符时间索引
  audio/                      音频元数据、资源释放
  render/                     纯 Canvas 渲染、钢琴几何布局
  export/                     MP4 编码、音频裁切、输出目标
  hooks/                      导入、播放、导出生命周期
  components/                 表单与预览组件
  server/                     HTTP 字节范围校验
  tempo/                      动态 BPM 分析、Worker、节拍与时间映射
  studio.tsx                  工作台编排
tests/
  unit/                       解析、长音符查询、区间、几何、Range
  e2e/                        文件导入、播放、导出与响应式验证
```

每个源码文件不超过 500 行，ESLint 对 TypeScript 文件执行 `max-lines` 检查。音符按起点排序，配合单调最大结束时间索引查询可见窗口，持续长音不会因后续短音结束而消失。

## 检查与测试

```bash
npm run lint
npm run typecheck
npm test
npm run test:e2e
npm run format:check
npm run build
```

端到端测试默认使用系统 Chrome；可复用已运行的 3000 端口服务，否则自动启动开发服务。测试会生成 MIDI / WAV，实际下载 MP4 并检查 H.264 / AAC 轨道、尺寸与时长。本地示例测试仅在媒体文件存在时运行。浏览器测试产物位于忽略的 `test-results/`。

定位诊断还会采集浏览器跳转后实际输出的 PCM 波形，与精确解码窗口做相关性比较，避免仅靠 `currentTime` 数字判断准确性。`native-seek-measurements.json` 保存测量结果。同步诊断导出音频 40:00 附近的两个短片：原始时间映射与 +154.5 秒 MIDI 候选位置。候选来自音乐音高特征匹配，仅供试听核对，不会修改应用默认值，也不代表整首曲子的校准结果。
